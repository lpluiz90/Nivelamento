Aviso importante

IA Generativa · Nivelamento Maj Luiz Paulo
Comece pelo quadro âmbar, e diga com todas as letras: ninguém aqui vai programar. Muita gente trava só de ver chaves e aspas na tela achando que é código — não é. É um formato de escrita, como uma ficha de papel tem campos.

Se alguém perguntar "então por que eu preciso disso?": porque é o formato em que se pede uma resposta organizada à IA, e é o formato em que ela devolve. Sem entender isso, a pessoa fica presa a respostas em texto corrido.
Bloco 1

O que é JSON

Antes da sintaxe, o problema que ele veio resolver.

Slide de respiro. Passe rápido.

O problemaDois programas precisam se entender

Um programa tem uma informação. Outro programa precisa dela. Só que programas não conversam — eles só trocam texto.

✗ Se mandar em texto solto

"O aluno João da Silva, de 15 anos, tirou 8,5 em matemática e 7 em português."

Uma pessoa entende. Um programa não sabe onde começa o nome, se "15" é a idade ou uma nota, nem o que fazer com a vírgula do 8,5.

✓ Se mandar organizado

{
  "nome": "João da Silva",
  "idade": 15,
  "notas": {
    "matematica": 8.5,
    "portugues": 7
  }
}

Cada dado tem nome e lugar. O programa pede "idade" e recebe 15. Sempre.

Isso da direita é JSON. É só isso: um jeito combinado de escrever informação para que qualquer programa saiba onde achar cada coisa.

IA Generativa · Nivelamento Maj Luiz Paulo
Não defina JSON antes de mostrar o problema — o formato só faz sentido depois que a dor aparece.

Leia a frase da esquerda em voz alta e pergunte: "está claro pra vocês?" Todos vão dizer que sim. Aí a virada: está claro pra você porque você é humano. Um programa não entende português, ele não sabe que "de 15 anos" quer dizer idade.

Depois mostre a direita e diga que aquilo é a mesma informação — só que arrumada de um jeito que a máquina consegue pegar campo por campo. E que aquilo já é JSON, a turma acabou de ver um sem saber.

O nomeDe onde vem a sigla JSON

JavaScript Object Notation

"Notação de Objetos do JavaScript"

A pergunta que sempre aparece

"Então eu preciso saber JavaScript?" — Não. O nome é só uma herança: o formato nasceu inspirado no jeito que a linguagem JavaScript escreve informação. Mas hoje ele é usado por qualquer linguagem e programa, e você não precisa conhecer nenhuma delas para ler um JSON.

É um arquivo de texto, com extensão .json. Abre no Bloco de Notas. Você consegue ler com os próprios olhos — e essa é a graça dele.

IA Generativa · Nivelamento Maj Luiz Paulo
A pergunta do quadro âmbar aparece em toda turma, sem exceção — antecipe antes que alguém pergunte, porque é ela que faz metade da sala achar que a aula não é pra ela.

Insista no quadro laranja: é texto puro. Não é um programa, não precisa instalar nada, abre no Bloco de Notas. Isso costuma desarmar quem estava intimidado.

Se perguntarem por que não usam algo mais simples ainda: já se usou muito o XML, que faz a mesma coisa mas é bem mais pesado de escrever e de ler. O JSON venceu por ser mais enxuto.

AnatomiaAs peças de um JSON, uma a uma

{
  "nome": "João da Silva",
  "idade": 15
}
{ }  abre e fecha a ficha inteira
"nome"  é a chave — o nome do campo, sempre entre aspas
:  os dois-pontos separam o campo do conteúdo
"João da Silva"  é o valor — o conteúdo
,  a vírgula separa um campo do próximo
Pense assim

É uma ficha de cadastro. A chave é o que está impresso no formulário ("Nome:"), o valor é o que você escreve na linha. As chaves { } são a borda da ficha.

IA Generativa · Nivelamento Maj Luiz Paulo
Vá apontando peça por peça, na ordem da lista da direita, e deixe o exemplo da esquerda na tela o tempo todo.

A palavra chave é infeliz em português, porque colide com as "chaves" { }. Diga isso explicitamente pra turma: são duas coisas diferentes com o mesmo nome. Se ajudar, chame de "nome do campo" em vez de chave.

A analogia da ficha de cadastro é a mais forte da aula inteira — volte a ela sempre que alguém se perder.
Bloco 2

Como se estrutura

Que tipos de conteúdo cabem num valor — e como se combinam.

Slide de respiro. Passe rápido.

Os tiposSó existem 6 tipos de valor

Depois dos dois-pontos, o conteúdo só pode ser uma destas seis coisas. Não existe uma sétima.

TipoComo se escreveServe para
Texto"qualquer coisa"nome, endereço, descrição — sempre entre aspas duplas
Número15   8.5idade, preço, quantidade — sem aspas
Verdadeiro/falsotrue   falsesim ou não: está ativo? já pagou?
Nulonull"este dado não existe / não foi informado"
Lista[ ... ]vários itens do mesmo tipo
Ficha{ ... }uma ficha dentro da outra
IA Generativa · Nivelamento Maj Luiz Paulo
Não decore a tabela com a turma — ela é referência, e os próximos slides destrincham um por um. O que importa aqui é a frase da abertura: só existem seis. É uma lista curta e fechada, o que torna o formato fácil de aprender inteiro.

Repare que os dois últimos (lista e ficha) são os únicos que contêm outros valores dentro. É isso que permite montar estruturas grandes a partir de peças simples — e é o que veremos adiante.

As cores da tabela se repetem em todos os exemplos de código da aula: verde é texto, laranja é número, roxo é true/false/null.

Tipos 1 e 2Por que número não leva aspas?

Com aspas = texto

"idade": "15"

O programa recebe os caracteres 1 e 5. Não dá para somar, nem comparar se é maior que 18.

Sem aspas = número

"idade": 15

O programa recebe a quantidade 15. Dá para somar, ordenar e comparar.

A pergunta que sempre aparece

"E o CPF? E o telefone?" — Vão como texto, mesmo sendo só dígitos. Porque ninguém vai somar dois CPFs, e porque como número o zero da frente sumiria: 011 viraria 11.

A regra prática: é texto se você nunca vai fazer conta com ele. É número se vai.

IA Generativa · Nivelamento Maj Luiz Paulo
Este é o primeiro ponto onde a turma trava, e a pergunta do CPF aparece sempre. Antecipe.

O exemplo do zero à esquerda é o que faz a ficha cair: telefone 011... guardado como número perde o zero e vira outro telefone. Ninguém esquece depois de ver isso.

Detalhe de português: em JSON o decimal usa ponto, não vírgula — 8.5, não 8,5. Isso confunde muito brasileiro, e é erro de sintaxe: com vírgula o JSON quebra. Se der tempo, mencione.

Tipos 3 e 4Sim, não… e "não existe"

true / false

"matriculado": true
"bolsista": false

Sempre em minúsculas e sem aspas. Em inglês mesmo — verdadeiro não funciona.

null

"telefone": null

Quer dizer: não temos esse dado. Diferente de estar errado — é a ausência declarada.

A confusão mais comum da aula

null não é zero. Não é texto vazio. Não é false.
0 = a nota foi zero  ·  "" = o campo existe e está em branco  ·  null = ninguém informou

IA Generativa · Nivelamento Maj Luiz Paulo
O quadro âmbar é o slide. Leia os três casos devagar, com um exemplo de prova: o aluno tirou zero na prova (nota 0) é diferente de o aluno faltou e não tem nota (null). Se você guardar null como 0, a média da turma despenca e ninguém entende por quê.

Guarde essa distinção — ela volta no bloco de IA, porque a regra "se não achar, retorne null" é o que impede a IA de inventar dado.

O detalhe do minúsculo e do inglês parece bobo, mas True com maiúscula (como se escreve em Python) quebra o JSON. Vale avisar.

Tipo 5A lista: quando tem mais de um

Colchetes [ ] guardam vários itens. Os itens ficam separados por vírgula, na ordem em que foram escritos.

Lista de textos

"materias": [
  "matemática",
  "português",
  "história"
]

Lista de fichas

"notas": [
  { "materia": "mat", "nota": 8.5 },
  { "materia": "port", "nota": 7 }
]

Use lista sempre que a resposta for "pode ter zero, um ou vários". Uma lista com um item só continua sendo uma lista.

IA Generativa · Nivelamento Maj Luiz Paulo
A pergunta que aparece aqui: "se só tem uma matéria, ainda preciso de colchete?" — Sim. Quem vai ler o dado precisa saber de antemão se aquele campo é uma lista ou não; mudar o formato conforme a quantidade é justamente o que quebra o programa do outro lado.

Mostre que a lista da direita tem fichas dentro — cada item entre { }, separados por vírgula. É a estrutura mais comum do mundo real, e é a que o próximo slide destrincha.

A confusão nº 1Quando é { } e quando é [ ]?

{ } — a ficha

Cada coisa dentro tem um nome. Você pega pelo nome.

{ "nome": "João", "idade": 15 }

"me dá o nome" → João

[ ] — a lista

As coisas dentro não têm nome. Você pega pela posição.

[ "João", "Maria", "Ana" ]

"me dá o primeiro" → João

O teste de um segundo

Pergunte: "cada item precisa de um rótulo diferente?"
Sim → { } ficha.  ·  Não, são todos a mesma coisa repetida → [ ] lista.

IA Generativa · Nivelamento Maj Luiz Paulo
Esta é a dúvida que mais volta depois da aula. O teste do quadro âmbar resolve 90% dos casos — ensine a turma a fazer essa pergunta sozinha.

Exemplo pra fixar: os dados de um aluno (nome, idade, turma) são coisas diferentes com rótulos diferentes → ficha. Os alunos de uma turma são todos a mesma coisa repetida → lista.

Se perguntarem: sim, dá pra ter lista de fichas (turma inteira), e ficha com lista dentro (aluno com suas notas). É a combinação dos dois que monta qualquer documento — o próximo slide mostra.

Tipo 6Ficha dentro de ficha

Um valor pode ser outra ficha inteira. É assim que se representa coisa complexa sem inventar formato novo.

{
  "nome": "João da Silva",
  "endereco": {                ← ficha dentro
    "rua": "Av. Brasil",
    "numero": 1500,
    "cidade": "Rio de Janeiro"
  },
  "materias": ["mat", "port"]   ← lista dentro
}

Repare que "endereco" não tem um valor simples — tem uma ficha inteira como valor.

Para chegar na cidade, o programa pede: endereco → cidade.

Não há limite de profundidade — mas na prática, mais de 3 ou 4 níveis vira difícil de ler.

IA Generativa · Nivelamento Maj Luiz Paulo
Aponte a indentação: os campos do endereço estão deslocados para a direita, mostrando que pertencem a ele. Diga que esse recuo é só para humanos lerem — o programa não liga, mas quem revisa liga muito.

Pergunta que costuma vir: "poderia ser tudo no mesmo nível, tipo endereco_rua, endereco_cidade?" — poderia, e às vezes se faz. A vantagem de agrupar é que dá pra pegar o endereço inteiro de uma vez, e fica óbvio o que pertence a quê.

A regra prática dos 3 ou 4 níveis não é técnica, é de legibilidade: JSON aceita quantos você quiser, mas ninguém consegue mais revisar.

Tudo juntoUm exemplo completo, com as 6 peças

{
  "aluno": "João da Silva",              texto
  "idade": 15,                            número
  "matriculado": true,                    verdadeiro/falso
  "telefone": null,                       nulo — não informado
  "endereco": {                              ficha dentro de ficha
    "cidade": "Rio de Janeiro"
  },
  "notas": [                                 lista de fichas
    { "materia": "matemática", "nota": 8.5 },
    { "materia": "português",  "nota": 7 }
  ]
}
chave texto número true / false / null
IA Generativa · Nivelamento Maj Luiz Paulo
Este slide não tem informação nova — é o fecho do bloco. Percorra com o dedo, de cima para baixo, nomeando cada tipo pela cor. Se a turma acompanhar os seis sem você explicar de novo, o bloco cumpriu o objetivo.

Uma boa checagem: peça pra alguém dizer, olhando a tela, quantas notas o João tem (duas) e qual o telefone dele (não informado — null, não é que ele não tenha telefone, é que ninguém preencheu).

Se sobrar tempo, apague mentalmente uma vírgula e pergunte o que aconteceria. É a deixa para o próximo bloco.
Bloco 3

O que quebra um JSON

Erros pequenos que fazem o arquivo inteiro parar de funcionar.

Slide de respiro. Passe rápido.

AtençãoOs cinco erros que quebram tudo

JSON é rígido: ou está perfeito, ou o programa recusa o arquivo inteiro. Não existe "quase certo".

{
  "nome": "João",
  "idade": 15,          ← vírgula sobrando
}
{
  'nome': 'João'       ← aspas simples
}
{
  nome: "João"         ← chave sem aspas
}
{
  // comentário  ← não existe em JSON
  "nome": "João"
}
{
  "nota": 8,5            ← vírgula no decimal
}
{
  "nome": "João",
  "nota": 8.5            ✓ assim funciona
}
IA Generativa · Nivelamento Maj Luiz Paulo
Percorra os cinco. Cada um é um erro que a turma vai cometer — e o mais traiçoeiro é o primeiro, a vírgula sobrando depois do último campo. Ela parece inofensiva e derruba o arquivo inteiro.

Aspas simples e chave sem aspas: os dois funcionam em JavaScript, e é justamente por isso que confundem quem já viu código. Em JSON, não.

Comentário: JSON não aceita nenhum tipo de comentário. Quem quer documentar precisa criar um campo, tipo "_obs".

Vírgula no decimal: erro clássico de brasileiro. Em JSON é sempre ponto — 8.5. Como a vírgula é o separador de campos, escrever 8,5 faz o programa achar que começou outro campo.

Na práticaComo saber se o JSON está certo

Você não precisa conferir de olho. Existe ferramenta que faz isso — e ela aponta a linha do erro.

Validador online

Sites de validação de JSON: você cola o texto e ele diz se está válido e, se não estiver, em que linha está o problema.

O próprio navegador

Arraste um arquivo .json para uma aba do navegador. Se abrir organizado, está válido. Se der erro, tem algo quebrado.

Regra de ouro: sempre valide antes de usar. Leva cinco segundos e evita horas procurando um erro que era uma vírgula.

IA Generativa · Nivelamento Maj Luiz Paulo
Não indique um site específico pelo nome — eles mudam, e qualquer busca por "validador JSON" traz vários. O importante é a turma saber que a ferramenta existe e que ninguém confere JSON no olho.

A dica do navegador é a mais prática de todas e quase ninguém conhece: arrastar o arquivo pra uma aba. Se estiver válido, o navegador mostra a estrutura organizada; se não, reclama.

Reforce a regra de ouro. Um JSON inválido não falha "um pouco" — o programa que ia consumir recusa o arquivo inteiro.
Bloco 4

JSON e Inteligência Artificial

Por que aprender isso muda o que você consegue pedir a uma IA.

Slide de respiro. Passe rápido.

A viradaPor que isso importa para IA?

Uma IA responde em texto para pessoa ler. Mas quase sempre quem vai usar a resposta é outro programa — uma planilha, um sistema, um relatório.

✗ Resposta em texto

"Claro! O aluno João da Silva tem 15 anos e está matriculado. Não encontrei o telefone dele."

Bonito de ler. Mas onde termina o nome? E se na próxima vez a IA escrever "João S." em vez de "João da Silva"?

✓ Resposta em JSON

{
  "nome": "João da Silva",
  "idade": 15,
  "matriculado": true,
  "telefone": null
}

Mesma informação, lugar fixo. O programa pede "idade" e recebe 15 — hoje, amanhã e daqui a mil respostas.

Pedir a resposta em JSON transforma a IA de alguém que conversa em alguém que preenche ficha.

IA Generativa · Nivelamento Maj Luiz Paulo
Pergunte: "as duas caixas dizem a mesma coisa?" Sim. "Então por que a da direita?"

A resposta está na palavra previsível. O problema do texto não é ele estar errado — é que a IA reescreve a frase de um jeito diferente a cada vez, e nenhum programa consegue depender disso.

Repare no null do telefone: no texto, a IA precisou de uma frase inteira ("não encontrei o telefone") pra dizer o que o JSON diz com quatro letras — e de um jeito que o programa entende.

O ponto centralO mesmo dado, escrito de cinco jeitos

Peça a data de nascimento a cinco pessoas — ou a mesma IA cinco vezes — e você recebe:

10/08/2011  ·  10-08-2011  ·  10 de agosto de 2011  ·  08/10/2011  ·  2011.08.10

Todas são a mesma data. Para um programa, são cinco textos diferentes — e a quarta é ainda pior: é a data americana, que troca o dia pelo mês.

Com o formato combinado antes:
"2011-08-10"
ano-mês-dia, sempre com 4 e 2 e 2 dígitos — não há como interpretar errado

JSON garante onde o dado está. Combinar o formato garante como ele vem escrito. Você precisa dos dois.

IA Generativa · Nivelamento Maj Luiz Paulo
Este é o slide mais importante do bloco — é o que responde "por que padronizar valores".

Leia as cinco datas em voz alta e deixe a turma perceber que são a mesma. Depois a pergunta: "qual delas o programa entende?" Nenhuma, sozinha — ele não sabe qual convenção você usou.

A quarta é a armadilha: 08/10/2011 em formato brasileiro é 8 de outubro, em formato americano é 10 de agosto. O mesmo texto, duas datas diferentes. Não há como o programa desempatar sozinho — e esse erro já causou prejuízo em sistema de verdade.

A distinção final é a lição: o JSON resolve metade do problema (onde achar o dado); a outra metade é combinar o formato do conteúdo. Muita gente aprende só a primeira e acha que está resolvido.

Cada linha da esquerda é um jeito de o mesmo dado chegar diferente. Quem define o formato antes não precisa consertar depois.

IA Generativa · Nivelamento Maj Luiz Paulo
Percorra linha a linha e peça exemplos à turma — todo mundo já viu planilha com data em três formatos diferentes na mesma coluna.

A linha do dinheiro merece parar: "R$ 1.500,00" é texto, tem símbolo, ponto de milhar e vírgula decimal. Como número em JSON vira 1500.00 — sem símbolo, sem ponto de milhar, com ponto decimal. O símbolo da moeda, se precisar, vai num campo separado.

A última linha liga com o slide do null: repare quantos jeitos as pessoas inventam pra dizer "não tem". Se cada um usar o seu, o programa não tem como saber que todos significam a mesma coisa.

AplicandoComo pedir JSON a uma IA

Não basta dizer "responda em JSON". Você precisa dizer exatamente quais campos e em que formato.

✗ Pedido vago

Extraia os dados do aluno
e me responda em JSON.

A IA inventa os nomes dos campos, e muda a cada vez que você pedir.

✓ Pedido com o molde

Responda apenas com este JSON:
{
  "nome": texto,
  "idade": número,
  "nascimento": "AAAA-MM-DD"
}
Se não encontrar, use null.
Não escreva mais nada.

Três frases que resolvem quase tudo: este molde · se não achar, null · nada além do JSON.

IA Generativa · Nivelamento Maj Luiz Paulo
As três frases do quadro laranja são o resumo prático da aula inteira. Cada uma existe por um motivo:

"Este molde" — sem o molde, a IA escolhe os nomes dos campos, e na segunda vez escolhe outros. Quem for ler o dado não consegue depender disso.

"Se não achar, null" — é a regra que impede a IA de inventar. Sem ela, quando falta o dado, o modelo tende a preencher com algo plausível, que é o pior erro possível: parece certo e ninguém confere.

"Nada além do JSON" — a IA adora começar com "Claro! Segue o JSON solicitado:". Essa frase sozinha invalida o arquivo, porque JSON tem que começar em {. É o próximo slide.

CuidadoO que costuma dar errado

A IA responde assim

Claro! Segue o JSON solicitado:

```json
{ "nome": "João" }
```

Espero ter ajudado!

O programa precisa disto

{ "nome": "João" }

Começa em {, termina em }. Nada antes, nada depois.

A simpatia da IA quebra o arquivo. "Claro! Segue:" não é JSON — e o programa recusa tudo, inclusive a parte que estava certa.

IA Generativa · Nivelamento Maj Luiz Paulo
Este erro é tão comum que vale mostrar ao vivo, se der: peça um JSON a uma IA sem avisar nada e veja se ela põe a saudação. Costuma pôr.

Explique o que são as três crases com "json" — é uma marcação de formatação, usada pra deixar o código bonito na tela do chat. Fica ótimo pra pessoa ler, e quebra pra quem vai processar, porque não faz parte do JSON.

A solução é a terceira frase do slide anterior: "responda apenas com o JSON, sem explicação e sem marcação". Vale repetir no fim do pedido — modelos costumam obedecer melhor à última instrução.

Slide de encerramento. Recapitule as três ideias, nesta ordem:

1) JSON é uma ficha — chave e valor, e só seis tipos de conteúdo possíveis. Não é programação, é texto organizado.

2) Ele é rígido — uma vírgula sobrando derruba o arquivo inteiro. Valide sempre antes de usar.

3) Ele resolve metade do problema. Diz onde cada dado está, mas não como ele vem escrito — isso é o formato, e você precisa combinar antes. Data, hora, dinheiro e "não informado" são os quatro que mais causam confusão.

Feche ligando com as aulas anteriores: na Aula 01, JSON era o formato em que a extração devolvia os campos. Agora a turma sabe ler aquilo.
